# Code signing

Release builds are signed automatically when the signing secrets below exist in the
repository (Settings, Secrets and variables, Actions). Without them the release workflow
still runs and produces unsigned installers, so forks and local builds keep working.

Signing certificates are issued to a person or organisation and cost money. They cannot be
generated by the project, so each maintainer supplies their own.

## Windows

Windows SmartScreen builds reputation per signing certificate. An EV certificate removes
the warning immediately; a standard (OV) certificate removes it after enough installs.

| Secret | Value |
| --- | --- |
| `WINDOWS_CERTIFICATE` | Your `.pfx` file, base64-encoded: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx"))` |
| `WINDOWS_CERTIFICATE_PASSWORD` | The password of the `.pfx` |

The workflow imports the certificate into the runner's store and passes its thumbprint to
Tauri, which signs the app, the NSIS installer and the MSI with SHA-256 and a DigiCert
timestamp.

Cloud-held keys (Azure Trusted Signing, DigiCert KeyLocker and similar) cannot be exported
to a `.pfx`. For those, set `bundle.windows.signCommand` in `src-tauri/tauri.conf.json`
instead; see the [Tauri Windows signing guide](https://v2.tauri.app/distribute/sign/windows/).

## macOS

Requires an Apple Developer Program membership ($99 a year). Create a
"Developer ID Application" certificate, export it as a `.p12`, and add:

| Secret | Value |
| --- | --- |
| `APPLE_CERTIFICATE` | The `.p12`, base64-encoded: `base64 -i cert.p12` |
| `APPLE_CERTIFICATE_PASSWORD` | The `.p12` password |
| `APPLE_SIGNING_IDENTITY` | e.g. `Developer ID Application: Your Name (TEAMID)` |
| `APPLE_ID` | The Apple ID used for notarisation |
| `APPLE_PASSWORD` | An [app-specific password](https://support.apple.com/102654) for that Apple ID |
| `APPLE_TEAM_ID` | Your 10-character team ID |

With the first three the app is signed; with all six it is also notarised and stapled, so
Gatekeeper opens it without a warning.

## Linux

Linux packages are not signed by this workflow.

## Installer artwork

The installer images in `src-tauri/installer/` are generated from `branding/logo.svg`:

```bash
npm run installer-art
```
